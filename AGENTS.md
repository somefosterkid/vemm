# Project instructions

## Product and architecture

This repository maintains **Vemm**, an independent, unofficial Samsung Tizen
Web Plex client. Vemm is a working brand, pronounced `/vem/`; trademark
clearance remains a separate decision. The canonical repository is
`dragoshont/vemm`; the archived predecessor preserves historical releases. The UI was
inspired by Gleb Linnik's PlxNative. Inherited code/catalogs remain
GPL-3.0-or-later, not clean-room or MIT-relicensed code. Read `LICENSING.md`,
`THIRD-PARTY-NOTICES.md` and `docs/vemm/`.

- `samsung/Vemm/`: shipped ES5 HTML/CSS/JavaScript app, public Tizen APIs and
  Samsung AVPlay. `main.js` composes the screens; `js/` owns reusable contracts.
- `samsung/locales/` and `samsung/strings.json`: translation inputs;
  `js/i18n.js` is generated by `tools/tizen/build-locales.js --write`.
- `samsung/Vemm/js/theme.js`: the theme tokens; `css/style.css` names colours only as
  `$tokens`, and `js/theme-rules.js` is generated by `tools/tizen/build-theme.js --write`.
- `samsung/{build,release,install}.py`: existing compatible WGT tooling.
- `tests/tizen/`: synthetic host contracts, DOM journeys and packaging tests.
- `tools/tizen/`: app-specific checks, benchmarks and isolated feasibility
  probes. Probes are not the product's renderer.
- `docs/samsung-tizen-client-spec.md`, `docs/vemm/`, `samsung/DESIGN.md` and `samsung/PRODUCT.md`:
  product/UX contract. Read the relevant portions before behavior changes.
- `docs/plex-openapi.json` and `docs/pms-api.md`: PMS protocol evidence; do not
  infer endpoint behavior from native historical implementation comments.

The LG Rust/C implementation, build, website and publishing tools were retired
from the active tree. Immutable historical references are documented in
`docs/samsung-repository-independence-plan.md`; do not restore obsolete native
instructions or run ARM/webOS gates for Samsung changes.

## Working rules

Make precise, finished changes. Preserve unrelated user work and generated
artifacts. Do not reset or clean a dirty worktree. Fix a reported bug by first
observing a failing regression/reproduction, then observing it pass.

Vemm is a separate application: preserve `VemmTvApp0` / `VemmTvApp0.Vemm`,
`vemm-tizen-*`, `Vemm-*.wgt`, `Vemm-source-*`, `v*` tags and the future Vemm
author identity. Never read or migrate historical Plx tokens/settings.
Keep experimental graphics off by default. Do not broaden playback capability
claims beyond source-backed model/firmware/runtime evidence.

Shipped code must parse as ES5 and avoid unsupported legacy APIs/CSS; reuse
existing lifecycle, cancellation, bounds, focus and fallback seams. Surface
errors explicitly. Do not bypass TLS/signature checks or silently drop a test
because its old source path was removed.

This repository is public. Never publish tokens, passwords, server addresses,
household media, DUIDs, certificates, SDK profiles or raw inspector records.
Legacy private/generated paths remain ignored even though their tracked
implementations were retired; never collect or delete those files as cleanup.
Use `TV_IP`, `YOUR_PLEX_TOKEN` and synthetic `.invalid` endpoints in examples.

## Verification

Read `docs/building.md` for the source/distribution loop. Install dependencies
only after a missing-dependency failure or an intended manifest change.

```sh
npm ci --prefix tests/tizen --ignore-scripts --no-audit --no-fund
tools/tizen/test.sh
tools/tizen/build-source.sh samsung/Vemm
```

The host suite includes inventory/routing/identity checks, locale/icon
freshness, packaging/source contracts and strict ES5/runtime checks.
Use the narrow test while iterating, then commit, confirm a clean tree and run
the full host gate on that exact committed candidate. Confirm it remains clean.
Audit related prose for contradictions and local links after behavior/removal
changes. A green host/unsigned SDK build is not Samsung hardware acceptance.

Device access, SDK installation, signing/certificate access and releases
require explicit authorization. Use the installed `tizen-tv-builder` skill
when available; the separate MIT toolkit is not a source dependency here.
For device work require a Samsung-specific exclusive lane and exact target,
then use synthetic accounts/media or explicitly disposable test records.
Household Guest/managed profiles are real people: do not automate writes to
their viewing state. No deploy, launch, reboot, certificate or Plex operation
is implied by a source-cleanup assignment.

## Integration and releases

Use short-lived branches; **main takes one squash commit per change**. Push or
merge main only with user approval. Fetch immediately before integration and
inspect divergence and exact changed paths; never squash an old index onto a
moving main and reverse other work. Do not force-push, rewrite tags or replace
published assets. Include the configured Co-authored-by trailer on commits.

`.github/workflows/samsung.yml` owns host CI and the explicit `vX.Y.Z`
publication route. Ordinary PR/main checks do not install SDKs, access signing
secrets or publish. Follow `docs/samsung-project-transition.md` for a separately
authorized release: clean source, exact version, matching complete source
archive, notices, checksums and Vemm-author signing; named-model rollout
is a separate acceptance step.

Use this repository's Issues and `SECURITY.md`, never the upstream author's
support/funding channels. Preserve history, releases and source offers.
The canonical repository is `dragoshont/vemm`; final trademark clearance and
any future old-fork handling are separate external operations;
do not delete/recreate the repository or discard metadata to simulate them.
